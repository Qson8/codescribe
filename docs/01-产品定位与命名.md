# 码著 CodeScribe · 产品定位与命名

> 定稿日期：2026-08-14
> 前身：CodeSucker（`fanbuz/codesucker`）· 软著代码抽取器
> 本仓库：`Qson8/codescribe`

## 1. 一句话定位

**码著 CodeScribe · 代码不出本机，文书一应俱全。**

把本地代码项目整理成软件著作权等**合规申报文档**的离线工具。全程离线、代码不出本机、规范内置、导出前自动校验。

## 2. 命名决策

| 项 | 名称 | 理由 |
|---|---|---|
| 中文名 | **码著** | ①「著」直接联想「软著」，SEO 关键词关联强；②谐音「码住」（收藏/存住），寓意「把代码妥善著录成册」；③两个字，好读好记 |
| 英文名 | **CodeScribe** | Scribe = 抄录员/著录员，与「码著」1:1 对应——产品本质是「把代码著录成规范文书」；短、无负面含义、好拼写 |
| 仓库名 | `codescribe` | 全小写，与英文名一致，符合 GitHub 惯例 |

### 2.1 命名决策依据

- 中文名负责「软著/著录」的搜索联想，英文名负责国际开发者与「文书 + 离线」定位，二者语义对齐。
- 改名零损失：GitHub 仓库改名会自动 301 跳转旧链接并保留全部 star/fork。
- 备选（未采纳）：
  - CodeSeal：封存 + 印章双关，品牌感强，但与中文名不同义。
  - 码证 CodeCert：证书导向，但易被误认成办证中介。

## 3. 定位核心资产（前身 CodeSucker 沉淀）

1. **注释/字符串感知的状态机清洗器**（Lexer 级，能正确识别字符串里的 `//`，30+ 后缀）
2. **敏感信息脱敏**（API 密钥/密码/内网 IP/手机号自动替换占位符）
3. **规范排版 + 显式分页 + docx 生成引擎**（页眉/页码/宋体 10.5pt 固定行距）
4. **三级风险校验引擎**（通过/警告/退回风险）
5. **core 包零 Electron 依赖**——架构上已为 CLI / Web / 企业私有化预留接口
6. **「代码不出本机」的隐私叙事**（离线优先，仅版本检测联网）

## 4. 定位约束（创始人拍板）

| # | 约束 | 结论 |
|---|---|---|
| 1 | 团队规模 | **单人开发** |
| 2 | 首选方向 | **接受先做「文档族」**（天花板低但能跑通付费） |
| 3 | 安检门定位 | **不当独立产品，当功能做**（详见 §5.3） |
| 4 | 获客渠道 | **按建议做（Inbound + 代办机构），但宣传暂无精力**——只靠自然流量，不投广告 |

## 5. 战略决策记录

### 5.1 改造方向评估（技能交叉验证）

> 评估所用框架：OST（机会/方案辨析）、MECE（结构化拆解 + 自审）、product-analysis（竞争位势）、pricing-strategy（变现）、grilling（决策收敛）

**OST 结论**：6 个候选方向全是「方案」，底层机会是同一件事——**中国企业在给代码「办证」「出境」「交付」时有大量格式合规苦活**。

**MECE 自审**：原 6 方向犯了 Axis Mixing，按单一轴「输出物类型」重排为 4 个能力族：

| 能力族 | 输出物 | 覆盖方向 | 综合评分 |
|---|---|---|---|
| **文档族** | 代码 → 合规文档 | 软著全家桶、交接/交付文档、SaaS 化 | ★★★★☆ 首选 |
| **安检族** | 代码 → 安全门禁 | 上云/出境安检 | ★★★★ 次选 |
| **智能族** | 代码 → 理解问答 | 企业私有化代码智能 | ★★★ 长期 |
| **盘点族** | 代码 → 量化报告 | 技术尽调/代码盘点 | ★★ 附加功能 |

### 5.2 竞争位势（product-analysis，当前 CPA0/CPA1）

- **文档族**：AI 文档工具（Mintlify/GitBook）是泛场景，国产软著工具多为简单拼接 → 软著垂直赛道无体验好的付费玩家，**有机会**。
- **安检族**：gitleaks/trufflehog/GitGuardian 全为开发者向 CLI/英文 → `GUI + 中文合规报告 + 审计日志` 是差异化（安全扫描是 table stakes，合规报告是 differentiator）。
- **智能族**：Cursor 私有化等新玩家增多但价格高 → 护城河深、销售重，solo 暂不碰。
- **盘点族**：代码资产量化是空白，但买方少、低频。

### 5.3 安检门场景澄清（用户疑问答复）

**场景**：开发者每天把代码片段粘贴给 ChatGPT/Cursor/Claude 让 AI 改代码，很多人直接把带 API Key、数据库密码、内网 IP、客户手机号的**生产代码**贴进去——这是国内公司最怕的「代码出境」合规风险。安检门 = 贴在「粘贴」动作之前的一道本地闸：粘贴前先扫一遍，把敏感内容自动脱敏/拦截，再放行给 AI。

**决策（结合 solo + 无宣传精力）**：不当独立产品做，当功能做。
- pipeline 已有脱敏模块，`core` 零 Electron 依赖，架构上就是为 CLI 准备的。
- 顺路发一个免费 CLI（复制代码 → 输出脱敏版），成本几乎为零，作为全家桶的**差异化卖点**。
- 不单独做 UI/落地页/分发。

### 5.4 变现策略（pricing-strategy）

| 能力族 | 价值度量 | 定价锚点 | 层级 |
|---|---|---|---|
| 文档族 | 按申报次数/项目数 | Next-best: 手工 2h≈1000 元 或 代办 2000 元 → **99–299 元/次 或 订阅 30–99 元/月** | 免费(基础导出)/Pro(全家桶)/服务商版 |
| 安检族 | 按 seat 或 CI 调用 | GitGuardian 企业版 $12–20/seat/月 → **19–49 元/seat/月** | 开发者免费/团队版/企业版(审计) |
| 智能族 | 按坐席 + 买断 | 私有化代码智能 10–50 万+/年 | 项目制报价 |

**关键洞察**：文档族低客单价靠订阅化提频；安检族天然适合 CI 集成的按用量；智能族价值最高但 solo 卖不动。

### 5.5 收敛方案（基于约束）

| 阶段 | 做什么 | 精力投入 |
|---|---|---|
| **0–3 月** | 文档族：软著全家桶（源程序 + 用户手册 + 设计说明书 + 申请表），核心全部复用现有 core，只加模板 | 低，纯改代码 |
| **附带** | 发一个免费 CLI 安检工具，作为差异化卖点，不做独立产品 | 极低，顺路 |
| **3–6 月** | 看文档族付费数据再决定是否扩安检族；智能族/盘点族无限期搁置 | 视数据 |
