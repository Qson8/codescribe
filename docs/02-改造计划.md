## 1. 目标回顾

从 CodeSucker 迁移全部代码（core 纯 TS 流水线 + Electron 桌面 app + design/docs 资产），将其改造为「码著 CodeScribe」。

**短期（0–3 月）核心目标**：
1. 文档族：软著全家桶（源程序 + 用户手册 + 设计说明书 + 申请表），复用 core 只加模板
2. 附带一个免费 CLI 安检工具（脱敏），作为差异化卖点，不做独立产品
3. 改名落实（码著 CodeScribe），保持离线、免费、自然流量增长

**中期（3–6 月）**：看付费数据决定是否扩安检族；智能族/盘点族无限期搁置。

## 3. 阶段 1：软著全家桶（0.5–2 月）

> 核心洞察：core 流水线（discover→clean→select→render→audit）完全复用，只加「文档类型」这一维度和新模板。

### 3.1 能力扩展：文档类型抽象
当前 core 是「单文档类型」（源程序）的硬编码。需抽象为多类型：

```
DocumentType = 'source-program' | 'user-manual' | 'design-spec' | 'application-form'
```

每个类型定义：
- 输入（需要用户填哪些元数据：软件全称/版本/成立日期/开发完成日期等）
- render 模板（docx 排版规则：页眉/页码/字体/行距）
- audit 规则（各自的合规校验项）

### 3.2 各文档类型规划

| 类型 | 产出 | 新增工作量 | 优先级 |
|---|---|---|---|
| 源程序（已有） | 60 页源程序文档 | 0（已完成） | P0 |
| 用户手册 | 从 README/代码注释/输入辅助生成用户操作手册 docx | 中 | P1 |
| 设计说明书 | 从架构/模块结构生成技术设计说明 docx | 中高 | P2 |
| 申请表 | 软著申请表字段引导填写 + 生成 docx | 低（表单为主） | P2 |

### 3.3 用户手册生成思路（P1，最有付费价值）
- 输入：软件全称 + 版本 + 简单功能描述（用户填写）
- 可选增强：扫描 README、代码注释提取功能清单
- 输出：规范的《用户手册》docx，含目录、章节（简介/安装/使用/常见问题/免责声明）
- 复用：render 引擎（docx 排版）+ audit 引擎（页数/章节完整性校验）

### 3.4 新增元数据输入
在现有 Step3 清洗页基础上，扩展「文档元数据」表单：
- 软件全称、版本号、开发完成日期、软件简称、著作权人、成立日期（V3 路线图已提到）
- 多文档共享同一套元数据，一次填写多文档复用

## 4. 阶段 2：CLI 安检工具（附带，0.5–1 月内顺路完成）

> 定位：差异化卖点 + 免费引流，不做独立产品、不做 UI。

- 形态：`npx @codescribe/cli scrub <file-or-dir>` 或复制粘贴文本 → 输出脱敏版
- 复用：`core/clean.ts` 的脱敏模块 + 状态机清洗器
- 输出：脱敏后文本（stdout）+ 敏感项统计（stderr）
- 亮点文案：「喂给 AI 前先过一道闸」
- 分发：npm 包，README 一句话说明，进 GitHub Release

### 验收
- [ ] 粘贴含 API Key/密码/内网 IP/手机号的代码 → 输出全脱敏文本
- [ ] 字符串字面量内的 `//` 不被误伤（复用状态机）
- [ ] `npm run verify` 通过

## 5. 阶段 3：付费化（2–3 月）

> 依据 pricing-strategy：先免费工具引流验证，再上付费。

### 5.1 免费/付费边界
| 层级 | 包含 | 定价 |
|---|---|---|
| 免费 | 源程序文档（现状功能） | 0 |
| Pro | 全家桶（用户手册 + 设计说明书 + 申请表）+ 自定义脱敏规则 + 校验项一键修复 | 订阅 30–99 元/月 或 99–299 元/次 |
| 服务商版 | 批量、多申报主体、API | 按需报价（待有用户后再做） |

### 5.2 付费实现方式（桌面 app）
- 选项 A：内置许可证校验（激活码/订阅制）
- 选项 B：免费版生成带水印/阉割版，Pro 去水印
- 推荐：先做 **Pro 功能门控**（非水印），付费墙简单可靠
- 支付：先走「一次性买断码」（微信/支付宝人工发码），验证意愿后再接自动订阅（LemonSqueezy/面包多等）

## 6. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 改包名后 Electron 打包/图标校验脚本失败 | 阻塞发布 | scripts 里的硬编码字符串需全量 grep 清理 |
| 用户手册生成效果差（AI 味/凑字） | Pro 不值钱 | 以「规范排版 + 可编辑 docx」为卖点，不承诺智能文笔 |
| 旧项目 `.codesucker.json` 兼容 | 老用户升级丢失配置 | 保留旧配置名读取兼容，或提供迁移提示 |
| 单人精力 | 拖延 | 严格按 0.5 月粒度切任务，先 MVP 后迭代 |
