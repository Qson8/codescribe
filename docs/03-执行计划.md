## 1. 总体架构决策

1. **core 保持纯 TS 零 Electron 依赖**——全家桶和 CLI 都复用它，不改架构方向
2. **文档类型抽象**：在 core 增加 `DocumentType` 概念（`source-program` / `user-manual` / `design-spec` / `application-form`），render/audit 按类型分发；现有源程序逻辑不动，新类型走扩展
3. **CLI 复用 `clean.ts`**：脱敏模块直接导出即可，CLI 只做 I/O 壳
4. **配置兼容**：`.codesucker.json` 保留读取兼容，新写 `.codescribe.json`
5. **改名自动化**：grep 全量替换 + 脚本化校验，避免人工遗漏（如 external-url 白名单、User-Agent、release 检测 URL）

## 4. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 改名遗漏（URL/User-Agent/白名单硬编码） | 更新检测/外链失效 | Task 1 用 grep 脚本全量替换 + verify 兜底 |
| render 重构破坏源程序 docx 兼容性 | 老用户文档格式错乱 | Task 5 必须字节级回归，禁止破坏现有输出 |
| 用户手册效果差（凑字/AI 味） | Pro 不值钱 | 卖点 = 规范排版 + 可编辑 docx，不承诺智能文笔 |
| 单人精力 | 拖延 | 任务全部 S/M 级，每 2-3 任务一 checkpoint，MVP 优先 |
| CLI 与 app 脱敏逻辑漂移 | 行为不一致 | CLI 直接 import core 导出，禁止复制粘贴实现 |
